# Flutter 调试实施计划

范围：Windows localhost，接入用户正在运行的鸿镜 Debug 构建；沿用 WDB 配对、任务、登录用户助手和CLI。Flutter通道直接连接 Dart VM Service / Inspector 服务扩展，不自动操作DevTools网页。

| 步骤 | 交付 | 验证与提交门槛 |
|---|---|---|
| F01 | 有界JSON-RPC、VM/isolate及能力发现、Widget查询/属性/等待、日志与内存诊断 | 协议夹具验证认证路径、目标歧义、超时/取消、断线不重放、Inspector对象组清理；独立提交 |
| F02 | flutter CLI、用户助手路由、联合观察、UIA操作与显式视觉兜底 | 路由/降级/取消测试与标准回归；独立提交 |
| F03 | 鸿镜真实闭环、配置说明、Agent Skill及交付包 | CLI→系统服务→助手→鸿镜；操作前后观察实际状态，恢复临时状态；分别记录协议、UIA、视觉结果；独立提交 |

执行原则：只连接明确的服务端回环地址；保留VM URI认证路径，展示和诊断隐藏其中凭据；可用时核对VM PID与窗口进程；多个isolate必须明确选择。Inspector引用不跨快照复用，任务结束尽力释放本次对象组并报告清理结果。Flutter观察能力按实际扩展探测，缺失时继续UIA/视觉，不将不可达误判为Release。UIA/Windows输入执行动作，Inspector不冒充完整测试驱动；结果未知时不自动换通道重复执行。未改应用源码、未连接真实设备的测试不算设备投屏业务通过。
