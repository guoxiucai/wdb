---
name: wdb
description: Use the Windows Debug Bridge CLI to deploy and validate Windows applications, debug Electron or Flutter UI, operate the interactive desktop through UIA and input, and retrieve screenshots, recordings, and logs. Applies when wdb is available; does not provide Android adb control.
---

Use `wdb` as the Windows device entry point. The current distribution is one pure-JavaScript npm tarball for Windows/macOS, using the user's Node >=22.0.0. Windows npm installs provide `wdb.cmd`; macOS provides a `wdb` shebang launcher. Check the actual command path to avoid an older portable package shadowing it. Legacy portable packages bundle Node and remain separate development artifacts. See `docs/NPM-CLIENT.md` for installation. For LAN setup or remote client validation, read [references/connection.md](references/connection.md). Distinguish same-host LAN-IP checks from cross-machine network acceptance; do not claim macOS, physical touch hardware, or real application acceptance from local fixture results.

1. Read `wdb --help`, `wdb devices --json`, and `wdb info --json` for the installed version, target, capabilities, and desktop status. With multiple devices, pass `--device <address|deviceId>`. First connect needs only `wdb connect <address>` and the Windows operator's dialog decision, with no manual fingerprint or pairing code. The CLI saves the first certificate automatically after approval; do not accept a changed saved fingerprint automatically. The same connect command reuses saved credentials.
2. Obtain `windows list`, then `ui tree` / `ui find` on the intended full window identifier. Use accessible controls when exposed. If multiple windows or controls match, inspect candidates and refine the target. GUI requires a logged-in, unlocked interactive desktop; report `DESKTOP_UNAVAILABLE` instead of trying to unlock or operate the secure desktop.
3. Choose the intended interaction path. `ui action` with `method: "uia"` directly invokes a control pattern; `method: "input", action: "click"` injects a mouse click at its bounds. Use `mouse`, `key`, or `text` when testing actual input. Text defaults to Unicode injection; keyboard/IME composition is a separate path. Preserve complete returned window IDs and `reference` objects. On `STALE_WINDOW` / `STALE_CONTROL`, observe again and locate a new reference.
4. After an action, read actual control/window state or wait for an expected state. Take a screenshot for visual fallback when controls are absent or insufficient. Screenshot artifacts include original dimensions, bounds, coordinate mapping, and display `layoutId`; map thumbnail points back to physical virtual-desktop coordinates. Pass `layoutId` for coordinate-sensitive actions. On `DISPLAY_CHANGED`, obtain fresh screen information and observations.
5. Retrieve artifact files with `pull`. CLI JSON is evidence of execution, not proof the business workflow or every pen stroke succeeded. Inspect screenshots, recording content, application logs, and exposed control state before judging the result.

Use `--json` for machine parsing and `--args-file <path>` for structured arguments, touch trajectories, or difficult shell quoting. Successful task submission is `accepted` / `running`; the final task result is obtained by automatic waiting or `task get|wait <id>`. Waiting uses SSE when advertised, with bounded polling fallback on older services. `--follow` streams existing stdout to stderr; ordinary JSON stdout remains a single result. Recover an interrupted stream on the same task, never by resubmitting it. Preserve request/task IDs, device IDs, errors, and artifact paths in validation records.

On macOS, argument/script/expression files and pull destinations are local Mac paths; JSON `path`/`cwd`, shell commands, CDP endpoints, and VM Service endpoints refer to Windows. Quote PowerShell with single quotes to prevent zsh expansion. Pull screenshots before viewing and retain Windows physical coordinates without Mac Retina scaling. Ctrl+C ends watch/follow; interrupting an ordinary task waiter does not cancel its server task. Use `task cancel` explicitly.

For Electron, read the package's `docs/ELECTRON.md`. Use `electron launch` with the observed application path and an unused local debugging port, or `electron targets` against an already enabled endpoint. The endpoint is local to the **server**, not the CLI. Select the exact returned page ID and Windows window ID; do not assume they are interchangeable. Single-instance apps may need a normal exit and relaunch before debugging flags apply. `cdpAvailable:false` does not prove a usable CDP session.

Use `electron observe` to combine DOM, UIA and screenshot evidence. Prefer CDP selectors or exact labels for web controls and UIA references for native controls. `electron action --backend auto` only falls back for confirmed pre-action lookup/unavailability failures; visual fallback requires explicitly supplied observed coordinates. After `ACTION_OUTCOME_UNKNOWN`, timeout, or an ambiguous target, reobserve rather than repeating or changing backend automatically. Keep CDP CSS viewport coordinates separate from physical desktop coordinates and screenshot pixels. A successful CDP action does not prove UIA or Windows input compatibility. `electron eval` can change the page; use it within the intended debugging scope, and use `wait`/state reads to confirm effects. Console capture is bounded to the requested interval. Self-authored temporary DOM panels test the mechanism, not the application's business workflow.

`devices` shows live state, hostname, address and persistent device ID. `enabled` is local selection permission; `connected` is the current probe result. Use `devices --watch` for recovery monitoring. Hostnames can collide; use address or device ID when ambiguous. Commands automatically reconnect for up to 60 seconds by default (`--reconnect-timeout`), and supported task submissions recover the same persisted task by submission ID. This does not authorize replaying an action after `REQUEST_OUTCOME_UNKNOWN` or `SERVICE_RESTARTED`. Explicit disconnect stays disabled until connect; certificate, identity and authorization failures require resolution rather than automatic pairing.

For Flutter, read `docs/FLUTTER.md`. Use the observed Dart VM Service URI, preserving its authentication path in a private args file; it is not the DevTools browser URL. Bind the full window ID to the VM PID and select an exact isolate when ambiguous. `flutter info` probes actual extensions; an unreachable endpoint does not prove a Release build. `flutter observe` continues with UIA and screenshots when the protocol is unavailable. Inspector reads widget diagnostics, while `flutter action` uses UIA or explicitly observed visual coordinates. Use creation locations and an `ancestor` selector to disambiguate repeated widget types. A widget's presence does not prove visibility: confirm relevant properties or screenshots. `flutter wait --property ... --value ...` compares diagnostic descriptions. Do not reuse snapshot paths or temporary Inspector handles as stable controls. Check `truncated` and `cleanup`; do not infer absence or uniqueness from a truncated tree. Profile/Release may lack Inspector. Memory snapshots are not CPU profiling, and a VM connection does not imply a complete Dart evaluator. Keep auth URIs and application logs out of shared reports.

Timeouts and network failures can occur after a side effect. Query the task and observe state before deciding whether to retry; do not automatically repeat install, click, or touch. `--wait-timeout` only limits client waiting, while `--timeout` requests a server execution limit. `disconnect` preserves authorization and is distinct from `clients revoke` and `task cancel`.

Long shell and deployment tasks continue across disconnects and can be queried after reconnect. Input tasks require the controlling CLI heartbeat; keep the CLI waiting until completion. They cancel and release held input on cancellation or control loss. Recordings run to a configured duration limit. File interruption fails that transfer and cleans its partial file; restart the transfer. Services restarting leave uncertain tasks interrupted/unknown rather than replaying them.

Use `shell --script` or `--script-file` for automation tasks. Bare `shell` is a persistent interactive terminal and requires TTY stdin/stdout; Ctrl+C goes to the remote program, Ctrl+] closes locally. Read `docs/STREAMING.md` for terminal and `forward` / `reverse` options. These streaming commands remain in the foreground and never reconnect or replay after failure; inspect state before starting a replacement. Forward/reverse accept only literal loopback TCP endpoints; `--json` reports NDJSON lifecycle events. Their leases are separate from GUI input ownership. Windows has the native ConPTY host; Mac terminal behavior requires separate real-machine verification.

Use `shell` with the default logged-in identity; specify `--admin` only for an operation needing administrative execution within the user's authorized task. Use `app launch` for GUI programs. Provide user-supplied installer identifiers and silent parameters; do not guess EXE silent flags or reboot automatically. Report manual intervention when a secure desktop or additional credentials are required.

Inspect `app list` scope before deployment. Use `--scope user` without `--admin` for per-user installers/uninstallers; use explicit `--admin` for machine deployment. Keep the exact application ID and observe registry/version/file state after execution; installer exit code alone does not prove replacement or removal.

File operations default to no overwrite; use `--overwrite` only when replacement is intended. Checksums and transport success do not prove an installer or application behaved correctly. Touch trajectories use true Windows touch injection, up to 10 active contacts; assess delivered input statistics separately from application rendering and stroke completeness.

For multi-finger failures, verify foreground state and `call windows.hitTest` at contact coordinates before attributing the failure to injection. Windows 11's **Bluetooth & devices > Touch > Three- and four-finger touch gestures** can consume application input even on a machine without a physical touch screen. If one/two fingers work but three or more do not, inspect this setting (`ms-settings:devices-touch`). For an authorized diagnostic comparison, record its original state, temporarily disable it, verify actual application events/strokes, and restore it afterward unless the user requested a lasting change. UIA controls supporting Toggle expose `toggleState`; observe before toggling and after restoration. The touch command does not change system preferences itself.

For command examples, schemas, credential locations, and file/coordinate semantics read the package's `docs/CLI.md` if available. Use `call <operation> --args-file <path>` for capabilities without a convenient command alias. Keep pairing codes and client tokens out of logs, generated scripts, commits, and shared reports.
