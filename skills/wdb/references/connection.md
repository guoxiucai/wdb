# Remote Windows connections

Both clients are portable: extract the whole CLI package, use Windows `bin\wdb.cmd` or macOS `bin/wdb` (bundled Node), and retain the package's docs. The Skill alone is not a CLI installation. Mac remote operations still run on Windows. The Mac launcher supports symlinks and paths containing spaces; it does not use a global Node installation.

First connect needs only `wdb connect <server-IP>`, followed by the server operator's consent dialog. Do not ask for a fingerprint or pairing code as a prerequisite. The CLI discovers the first certificate through TLS and pins every subsequent request, saving trust only after approval. This is trust on first use; optional `--fingerprint` supports prior verification, and a changed saved fingerprint still fails. Don't scan neighboring hosts or copy another client's credential store. Reconnect with the same command. Do not put credentials in shared output. Use `--config <local-directory>` consistently for an isolated test profile. If the CLI still demands pairing materials, replace the old client package; an old server returning PAIRING_DENIED also needs upgrading.

The server operator chooses Allow/Deny and whether to remember an allowed client. Unremembered authorization ends on disconnect, service restart, or 30 minutes without authenticated activity. `PAIRING_REQUIRED` / `approval_required` means explicit connect must request local consent again; do not silently retry, approve the dialog for the operator, alter stored authorization, or treat rejection as a connectivity error. New connect waits up to 150 seconds by default (`--approval-timeout`); server dialog expires after 120 seconds. Remembered legacy credentials remain valid. The LAN validation script disconnects/reconnects, so an unremembered client will need another local approval during that step. See package `docs/CONNECTION-APPROVAL.md` for the protocol and precise lifecycle.

Mac configuration precedence is `--config` > `WDB_CONFIG` > `~/Library/Application Support/wdb/client`. An absent default directory can import the legacy `~/wdb/client/devices.json`; an existing directory is never merged. Mac config directories/files use 0700/0600, including existing profiles. There is no general multi-process config lock. Pairing and temporary authorization renewal use the shared Windows consent flow described above.

Run `wdb devices --json`, then `wdb info --device <address> --json`. The displayed hostname is a label, the URL is the network address, the 16-character device ID is the persistent identifier, and the certificate fingerprint establishes trusted identity. Same device at multiple saved addresses can be ambiguous: use the exact address. A changed IP does not authorize trusting a changed certificate.

`connect` prints one brief result; with `--json`, its envelope data contains only `address` and `state` (`connected`, `already_connected`, `failed`, `timeout`). Read identity, capabilities and desktop details from `info`; clientId, fingerprint and remembered are in `info.data.connection`, not the connect result. Already connected is reported only after a successful online/authentication check. A timeout with `REQUEST_OUTCOME_UNKNOWN` still requires observing server state before retrying.

For the standard delivery smoke check, run the client package's `runtime\node.exe scripts\validate-lan.js --device <address> --output <local-result-dir>`; append `--config` if applicable. It creates and cleans a unique remote temp directory, verifies file bytes, queries screens/windows, pulls a screenshot and disconnects/reconnects. It does not perform application clicks or measure LAN throughput. Inspect the resulting screenshot and report, preserving the distinction between transport and business validation. Use package `docs/LAN.md` for separate interruption, restart and performance steps.

On Mac use `./runtime/node ./scripts/validate-lan.js --device <address> --output <local-result-dir>`. Verify the package offline with `./runtime/node ./scripts/verify-package.js`. Package validation does not prove LAN authentication or a real Windows desktop interaction passed.

Only the Windows server's HTTPS port (default 18766) is exposed to the LAN. Desktop helper, CDP and Dart VM Service remain server-local; `--endpoint http://127.0.0.1:...` is interpreted on the server. Don't open those debug ports for a remote client. Windows remote file paths remain Windows paths; local artifacts use the client's filesystem. `--args-file` and `--script-file` are read locally and their contents sent to the server.

Server network/installation management scripts restart services and must execute outside a WDB shell child process. Use an authorized local administrator terminal, or an independently managed deployment process. Don't disable the firewall or change network category as a generic connection fix. Server GUI requires its logged-in, unlocked desktop; Mac client permissions cannot fix an unavailable Windows desktop.
